# 开场流程原型：温室留言

这是在 P0 生态温室上接入的短流程，用于验证任务、UMG 档案与培育的数据链路。它不是完整 1.0，也不计为 30–45 分钟的 P1「无访花房」样章。没有新增收费素材、生成请求或配音服务。

## 运行与实际操作

双击工程根目录 `打开开场流程试玩.bat`。启动独立 `BuildOutput-Prologue` 打包版，并传入 `-VZStory`。不带该参数运行时仍是 P0 测试模式。

1. 跟随「档案台」标记，靠近按交互键（默认 E），阅读温室留言。
2. 前往花床，按扫描键（默认 Q）。交互键或面板按钮关闭记录。
3. 按位置与距离标记寻找三份活性样本，靠近交互。顺序自由，同一位置只能采一次。
4. 返回培养台，交互消耗三份样本，确定获得第二个 V-001 个体「新芽」。初芽及其 GUID 保留；新芽有不同 GUID，队伍有空位时自动加入。
5. 前往协作练习节点，交互激活。扫描标记，脉冲／护盾／伙伴技能与移动躲开预警。该节点是训练装置，不能计为花庭守护者。
6. 平息节点后返回花床交互，改变花床状态，记录初芽经历，获得两份研究样本。
7. 回档案台提交记录。以后可再次查阅已经完成阶段的记录；尚未完成阶段的文本不提前展示。

Esc 暂停菜单提供三手动槽、自动槽、难度、音量和键位设置。死亡不消耗伙伴、样本或任务记录。培育后的主角死亡会按已存队伍重建两个伙伴。

## 数据与失败边界

- `main.prologue` 保存 0–7 的任务阶段。采集位置、修复、个体、材料与每次事件回执在同一个候选世界状态中提交。
- 首次培育无概率、不消耗父代；这只是 V-001 确定性研究配方，还没有通用杂交 UI、研究概率和完整 12 物种配方。
- 不合法事件、不足材料、重复采集／培育／修复会拒绝，失败候选不改变原状态。
- 自动保存失败时不替换实时状态。任务不会显示已经完成，也不会仅在内存中发奖。
- 原型玩家存档位于本包 `Saved/SaveGames/ProloguePrototype`；P0 存档继续使用其原目录。自动化运行另外使用随机 GUID 目录。
- 暂停菜单和死亡恢复会关闭对话、释放移动与视角锁。战斗过程中不能打开档案以规避操作限制。

## 验证边界

原生测试 `VariantZero.Story.PrologueTransactions` 覆盖越级事件、任意顺序采集、重复采集、缺料、培育中途保存／读回、父代身份、唯一新个体、奖励读档去重。

`VZStoryTest` 从真实角色交互入口执行流程，检查保存保护、UMG 面板、暂停交接、两个伙伴生成、死亡与读取、修复材料数量、回访档案。战斗在这项流程测试中通过注入伤害结束，不能据此声称玩家完成战斗或通过新玩家可用性验收；战斗行为由独立 `VZCombatTest` 回归。

脚本：`Scripts/build_prologue.ps1`、`Scripts/test_prologue_package.ps1`、`Scripts/test_native.ps1`。打包结果以 `prologue-packaging.log` 和 `prologue-verification.json` 为准。
