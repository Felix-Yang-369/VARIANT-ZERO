# 跨版本存档与迁移

从共享存档版起，正常「开始游戏」的主线进度保存在：

`%LOCALAPPDATA%\VariantZero\SaveGames\Story`

不同试玩版本使用同一目录，自动槽 `slot_0.vzsave`，手动槽 `slot_1.vzsave` 至 `slot_3.vzsave`。每槽保留 `.bak` 备份。项目根目录「打开存档文件夹.bat」可以定位目录；首次保存前不会创建空存档目录。

旧版可执行文件仍使用旧路径，因此回到旧版游玩不会修改新的共享进度。编辑器技术测试、自动化测试与非主线模式也保持隔离。声音、按键等设置本轮尚未迁移到共享目录。

## 旧档迁移

首次启动主线模式时，若共享目录不存在，检查当前包的 `Saved/SaveGames/ProloguePrototype`。也可在启动参数中明确提供其他旧版目录：

`-VZStory -VZLegacySaveDir="D:\旧包\Windows\VariantZeroUE\Saved\SaveGames\ProloguePrototype"`

这只迁移 UE 主线存档，不能导入网页 JSON。不会扫描所有磁盘、混合不同版本的槽位，或猜测哪套旧档是玩家想保留的。

流程为四槽及备份校验 → 复制到临时目录 → 再次读取校验并逐字节比较 → 一次性提交整个目录。原始旧档始终保留；若主文件损坏但备份正常，可以从备份恢复。未来版本或无法恢复的损坏会阻止整组迁移及保存，不会留下半套可用进度。失败的临时目录保留供排查。

共享目录已经存在时不覆盖、不合并；仍沿用其中的数据及版本保护。成功迁移会留下 `migration.txt`，记录来源和备份恢复情况。当前项目各旧试玩包未发现主线正式存档，因此本轮未迁移或改写玩家进度。

## 验证

新增原生测试覆盖多槽迁移、源文件逐字节保留、备份恢复、目标不覆盖、单槽损坏时整组阻断、未来版本拒绝。原有自动保存、恢复和任务流程通过打包回归。未将这项存档基础工作视为完整 1.0 已完成。
